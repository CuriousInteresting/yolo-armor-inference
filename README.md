# YOLO26 Pose 装甲板检测与关键点推理

> 基于YOLO26n的 `best.pt` 权重，对自行拍摄的机器人装甲板视频进行离线推理，输出检测框、类别、置信度和每个装甲板的四个预测关键点，并保存可播放的结果视频。

## 1. 项目介绍与已实现功能

本项目使用 **Ultralytics YOLO Pose** 推理接口和 OpenCV，实现以下功能：

- 加载提供的装甲板姿态估计模型 `weights/best.pt`。
- 读取本地视频 `videos/original.mp4`，逐帧执行推理。
- 使用模型提供的六个类别名称：`B1`、`B2`、`B3`、`R1`、`R2`、`R3`。
- 为检测到的装甲板绘制**检测框、类别、置信度**。
- 绘制模型直接预测的**四个关键点**及其连线，并显示 `LT`、`LB`、`RB`、`RT` 标识。
- 将带标注的视频写入 `results/output.mp4`。

**说明：**模型支持六类输出，不等于本次短视频中已实际出现或成功识别全部六类。本次实验截图主要展示了 `B2`、`B3` 的检测情况。关键点来自 Pose 模型的预测结果，**不是检测框四角的替代值**。

本作业仅实现**离线视频检测与关键点可视化**，没有实现 PnP 测距、云台控制或实车自动瞄准。

## 5. 安装与运行

### 5.1 创建和激活 Conda 环境

在 Windows 的 Anaconda Prompt 或已经配置好 Conda 的 VS Code 终端中，运行：

```bash
conda create -n yolo26 python=3.10 -y
conda activate yolo26
```

若 `yolo26` 环境已经存在，只需激活，无需重复创建。

### 5.2 安装依赖

在项目根目录执行：

```bash
python -m pip install -r requirements.txt
```

PyTorch 的 CPU/CUDA 安装包与机器配置有关；若安装或 CUDA 识别失败，应根据实际系统、显卡和 PyTorch 版本选择兼容的安装方案。不要假定任意 CUDA 版本都适用。

### 5.3 执行推理

在包含 `infer.py` 的项目根目录中执行：

```bash
python infer.py
```

按照当前推理脚本的配置：

```python
MODEL_PATH = "weights/best.pt"
VIDEO_PATH = "videos/original.mp4"
SAVE_PATH = "results/output.mp4"
```

程序会逐帧读取视频并绘制识别结果。若弹出视频窗口，请让程序处理到视频结束；**提前按 Esc 退出可能只保存部分帧**。

运行完成后，检查：

```text
results/output.mp4
```

确认它能够正常播放，且包含检测框、类别、置信度及对应四个关键点。

## 7. 推理效果与真实实验截图

下面四张均为实际推理过程的截图；既展示成功案例，也保留类别冲突和漏检等问题，不通过手工篡改结果来美化表现。

### 7.1 单个 B3 装甲板成功检测

![B3 单目标检测，置信度约 0.83，绘制了四个关键点](images/01_success_B3.png)

**观察：**画面中正面装甲板被标注为 `B3 0.83`，检测框和 `LT/LB/RB/RT` 四个关键点能够覆盖目标的主要区域。这是本次实验中较清晰的成功案例。

### 7.2 同一帧多装甲板检测

![同一帧识别两个 B2 装甲板](images/02_multi_armor_B2.png)

**观察：**同一机器人画面中出现两个 `B2` 检测结果，置信度约为 `0.50` 和 `0.25`。两处目标分别具有检测框和关键点预测。这说明程序可以处理同一帧内的多个候选目标，但**不证明所有类别标签都正确**。

### 7.3 同一区域 B2/B3 类别冲突

![左侧装甲板在同一位置出现 B2 与 B3 重叠预测](images/03_class_confusion_B2_B3.png)

**观察：**左侧同一装甲板区域存在位置重叠、类别不同的候选框（`B2` / `B3`），属于**重复预测与类别混淆**现象；不能将其计为两个真实装甲板。

**可能原因（尚未通过对照实验逐项证实）：**装甲板数字纹理相似、拍摄角度和目标像素大小影响分类，以及类别感知的非极大值抑制（NMS）未去除跨类别重叠框等。

**建议的后续验证：**保存同帧候选框坐标与置信度，计算重叠框 IoU；对比不同 `conf` / `iou` 参数及类别无关 NMS 后处理的效果。提高阈值仅会过滤低分候选框，并**不能直接证明类别预测变得正确**。

### 7.4 左侧装甲板漏检

![左侧可见装甲板未出现检测框，右侧 B3 有结果](images/04_left_armor_miss_detection.png)

**观察：**左侧可见带数字的装甲板，但该帧没有输出对应检测框和关键点；右侧装甲板有 `B3` 检测结果（约 `0.38`）。属于**可见目标漏检**。

**可能原因（待进一步验证）：**目标侧视角、数字区域成像质量、训练场景差异，以及候选置信度未通过阈值等。仅凭这一帧无法确定唯一原因。

**建议的后续验证：**对比 `imgsz=640` 与更大输入尺寸的预测结果，检查降低阈值后是否出现左侧候选框，并对多帧结果进行统计，避免仅凭单帧下结论。

## 8. 关键点定义与注意事项

本项目绘制四个预测关键点：

| 名称 | 含义 |
| --- | --- |
| `LT` | 左上（Left Top） |
| `LB` | 左下（Left Bottom） |
| `RB` | 右下（Right Bottom） |
| `RT` | 右上（Right Top） |

当前可视化脚本使用的关键点下标映射为：

```text
0 → LT
1 → LB
2 → RB
3 → RT
```

该映射是依据当前推理结果调整的**程序约定**。正式使用前应与训练数据的关键点定义核对，不能只凭某一帧的几何位置推断整个数据集的标签顺序。关键点全部来自 `result.keypoints`，**不使用边界框四角代替模型预测**。

## 9. 问题记录与改进计划

| 观察到的现象 | 已采取的处理 | 后续可验证的方向 |
| --- | --- | --- |
| Pose 关键点数组解包报错 | 根据实际输出的 `(x, y)` 结构读取关键点 | 保留输出维度检查，兼容 `(x, y, conf)` 的情况 |
| `B2` / `B3` 在同一区域重叠出现 | 保留原始结果供分析，尚未声称彻底解决 | 计算 IoU，对比 NMS 和阈值设置；检查数据类别质量 |
| 部分装甲板漏检 | 保存相应视频帧作为失败案例 | 对比不同输入尺寸、阈值和视角，做多帧测试 |
| 姿态变化时关键点不够稳定 | 显示模型输出点和连线，便于检查 | 核对标注顺序，比较更多姿态样本 |

本次没有重新训练模型，也未完成系统性的精度测试，因此**不提供未测量的准确率、mAP、FPS 或推理加速百分比**。
